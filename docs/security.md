# Security review (M8, NFR-SEC-01)

Reviewed 2026-11-21 against the OWASP Top 10 basics listed in NFR-SEC-01. Every point names
the mechanism and the automated test that keeps it in place.

| Area                                | Mechanism                                                                                                                                                                                                                                                                                                                            | Guarded by                                                                                                                                            |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Authorization on every endpoint** | Default-deny guard: a route needs a session unless it declares `config.public`; admin routes declare `config.admin` (ADR 0005). Single business (D1): no per-user resources, so role checks are the resource checks.                                                                                                                 | `security.test.ts` walks the real route table: exactly 5 public routes; every other route → 401 anonymous; every admin route → 403 for a normal user. |
| **Authentication**                  | argon2id, min. 10 characters, forced change of bootstrap/reset passwords, login throttling (5 failures → 1 min per username, 20 per IP), timing-equalized unknown users.                                                                                                                                                             | `auth.test.ts`, `rate-limiter.test.ts`                                                                                                                |
| **Sessions**                        | Random 256-bit token in an HttpOnly, SameSite=Strict, Secure-behind-HTTPS cookie scoped to the ingress path; only its HMAC is stored; logout / deactivation / password reset delete sessions server-side.                                                                                                                            | `auth.test.ts`                                                                                                                                        |
| **CSRF**                            | `X-CSRF-Token` required on every state-changing request; per-session token after login.                                                                                                                                                                                                                                              | `auth.test.ts`                                                                                                                                        |

## Accepted risks / notes

- **Login twice under Ingress** (D4) – Home Assistant login plus app login. Accepted for v1.
- **Direct port (AR-14)** is plain HTTP; `DOCS.md` advises to enable it only in the home network
  or behind an HTTPS reverse proxy.
- **Rate-limit state is in memory** – resets on restart (single container, acceptable).
- **No DB triggers** protect finalized invoices – enforcement is in the application (row locks,
  status checks, tests). Triggers would need extra privileges in the HA MariaDB app (binary
  logging), which could break installations (decision D5: cheap safeguards only).
- **MCP over the direct port** (FR-MCP-12) – plain HTTP unless the owner puts it behind HTTPS;
  the bearer token travels in every request. Off by default; `DOCS.md` explains the setup.
- **Prompt injection** (NFR-MCP-02) – tool results contain user data (customer names, texts).
  Whatever an assistant is tricked into, it can only create or change drafts, which a person
  checks before finalizing.
- **JSON export** is a full copy of business data (without password hashes) – admins only; the
  file must be stored safely.
